A product beyond the invitation

The repository includes builder, recipient invitation, guest, dashboard, template-studio, and theme-studio routes. These show an application implementation rather than only a visual concept. Route presence alone does not prove a finished or deployed flow.

A deliberate template boundary

The inspected applyTemplateVersion function copies a template definition into an invitation and records a template/version pin. Republishing a template therefore does not have to mutate invitations already created from it. Themes and structured blocks support reuse without hardcoding each event.

Saving is part of the experience

Inspected tests cover delayed backend confirmation, failed writes, missing rows, retries, and draft/publish ordering. These are meaningful failure scenarios for a builder: an interface should not imply that work is saved until the backend confirms it.

What is established

Source implements product routes and version-pinning logic, and the repository includes focused regression tests. Those tests were inspected, not executed as part of this portfolio build. The original README includes a build brief and Lovable provenance; its requested features are not treated as shipped outcomes.
